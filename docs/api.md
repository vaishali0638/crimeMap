# API Design Outline (`/api/v1`)

> Phase 0 outline. The OpenAPI 3.1 document is generated by FastAPI from Pydantic models starting in
> Phase 1, linted in CI (`@redocly/cli lint`), and exported to TypeScript types (ADR-011). This file
> records the conventions every endpoint must follow.

## 1. Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1`; breaking changes → `/api/v2`, with `Deprecation` and `Sunset` headers on v1 for ≥ 1 release |
| Naming | snake_case JSON fields; plural nouns for collections; no verbs in paths (state transitions are sub-resources, e.g. `POST /pattern-reviews/{id}/decisions`) |
| Auth | Bearer JWT from the BFF; every route declares a permission code (startup check fails otherwise) |
| Request ID | Accept `X-Request-ID` (UUID) or generate one; echoed in responses, logs, audit events |
| Validation | Pydantic v2 with `extra="forbid"`; enums strict; bounded strings, arrays, bbox, and periods |
| Pagination | Cursor-based (`cursor`, `limit` ≤ 100) with stable sort `(sort_key, id)` |
| Field selection | `fields=` allow-list per resource; disallowed fields rejected, not ignored |
| Errors | RFC 9457 problem details (obsoletes RFC 7807), `application/problem+json`; stable `type` URIs; no stack traces or SQL |
| Security headers | `Strict-Transport-Security`, `Content-Security-Policy` (incl. `frame-ancestors 'none'`), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` (API; the web app uses `same-origin`, see ADR-025), `Permissions-Policy` (geolocation, camera, microphone disabled) — set by NGINX/BFF and API, tested in CI |
| Caching | `Cache-Control: private, no-store` on all data responses |
| Rate limits | Per user and per IP; `429` with `Retry-After` |
| Out-of-scope | Filters outside scope → `403` (audited); resource IDs outside scope → `404` |

## 2. Standard analytics response envelope

```json
{
  "data": { "...": "..." },
  "meta": {
    "request_id": "1b4e…",
    "filters_applied": { "region": ["PDY"], "category": ["property_theft"], "period": "2026-07-01/2026-09-30", "time_basis": "occurrence" },
    "record_count": 1284,
    "excluded_count": 83,
    "excluded_reasons": { "missing_location": 61, "missing_occurrence_time": 22 },
    "suppressed_cells": 4,
    "data_freshness": "2026-10-11T05:12:00Z",
    "method": "hex_grid_count",
    "method_parameters": { "cell_size_m": 500, "crs": "EPSG:32644" },
    "caveats": ["Synthetic boundaries — not official jurisdictions."],
    "classification": "RESTRICTED",
    "environment": "DEMO",
    "evidence_snapshot_id": null
  }
}
```

The frontend's analysis header component renders this block; a response without `meta` fails the
contract tests for any analytics or map endpoint.

## 3. Error catalogue (initial)

| Status | `type` (suffix of `https://crimemap.local/errors/…`) | When |
|---|---|---|
| 400 | `invalid-request` | Malformed parameters |
| 400 | `invalid-cursor` | Malformed or tampered pagination cursor |
| 401 | `unauthenticated` | Missing/expired token |
| 403 | `forbidden` | Permission missing |
| 403 | `out-of-scope` | Filter outside the user's territory/classification scope |
| 403 | `reauthentication-required` | Step-up needed (exports, sensitive actions) |
| 404 | `not-found` | Missing or out-of-scope resource |
| 409 | `invalid-state-transition` | Workflow precondition failed |
| 409 | `separation-of-duties` | Self-approval or one person filling both approval slots |
| 413 | `payload-too-large` | Upload/request too large |
| 415 | `unsupported-media-type` | Upload type not allowed |
| 422 | `validation-error` | Field errors (with `errors[]`) |
| 422 | `query-too-broad` | Bbox/period/feature limit exceeded |
| 429 | `rate-limited` | Rate limit |
| 503 | `feature-disabled` | Feature flag or AI kill switch off |

### Phase 3 endpoints as built (revised by the Phase 3 audit)

| Endpoint | Notes |
|---|---|
| `GET /filters/metadata?region=` | Regions, stations, beats, categories, statuses and period limits inside the caller's scope. If the region is omitted, the caller's first region is used. Sensitive categories are listed only for callers whose sensitive-category access covers the region. |
| `GET /map/features?region=&station=&beat=&category=&record_type=&status=&period_from=&period_to=&time_basis=&min_confidence=&aggregation=POINTS\|HEX\|BEAT&hex_size_m=250\|500\|1000\|2000&bbox=&purpose=` | Returns GeoJSON and `summary` (selected, usable, shown, excluded by reason, and a constant "not counted" rule for small sensitive groups), `legend`, `aggregation` (requested, used, reason), `period`, `about` and `data_label`. More than 3,000 points falls back to HEX with a reason. The period must be at most 731 days and lie between 2000 and next year (otherwise 422; `query-too-broad` for length). A territory outside scope → 403 `out-of-scope` (audited). A sensitive category without sensitive access → 403 (audited). `bbox` selects by the coordinate returned. `purpose=DQ_REVIEW` gives a steward exact points for records under location review only. |
| `GET /search?q=` | Authenticated; each part applies its own permission. Case-reference prefix (`incident.summary.read`, sensitive only with access), units, localities (`map.points.read`; sensitive records left out of counts), categories (sensitive only with global sensitive access), and a `period` for `YYYY-MM` or `YYYY-MM-DD`. `not_available` lists landmark and road search (no data yet). The audited query has phone, Aadhaar-like, PAN-like, vehicle-registration and email patterns redacted; names cannot be detected. |
| `GET /incidents/{id}/summary`, `GET /incidents/{id}` | Fields per role (data-classification §3); hour-level times are the IST hour. Out of scope, or sensitive without permission → 404 (audited). |
| `POST /incidents/{id}/data-issues` `{"issue_type","note"}` | The only incident write: it creates a USER DQ issue (`detail.reason` = the note) and never changes the record. 409 while that flag is open; flagging again after it was resolved or accepted reopens it (the original reason is kept). |
| `POST /operational-records`, `GET /operational-records?review_status=&kind=&limit=` | No FIR kind. The station and beat are found from the point; a territory outside scope → 403. A referenced incident must be visible to the caller (territory, classification, sensitive category) and in the record's region, otherwise 404 (audited; indistinguishable from a missing id). 503 civic (flag off), 422 action completion (recorded on the action since Phase 6). Lists leave out records about incidents the caller cannot see; points are exact for the author and exact-location scope, otherwise snapped to 250 m (`precision: GRID`). |
| `POST /operational-records/{id}/reviews` `{"decision","note"}` | 409 `separation-of-duties` for your own record; 409 `invalid-state-transition` if already decided (concurrent reviews are serialised). A data steward may decide location corrections only. |
| `GET /map/operational-records?region=&period_from=&period_to=` | Approved event markers and observations (observations need no review), as points in the caller's territory; another region → 403 (audited). Exact or snapped as above. |
| `POST /notes`, `GET /notes?subject_type=&subject_id=\|subject_key=` | Append-only notes; the API returns plain text, which the UI escapes. A cell note belongs to the station holding the cell's centre; outside the caller's territory → 404 (audited). Up to 200 notes, oldest first. |
| `GET /review-queue/summary` | Badge counts: open or assigned DQ issues within `dq.manage`, and pending operational records the caller may decide; since Phase 6 also `pattern_reviews`, `actions` and `outcomes` (the same items as the queues; `null` when the caller has no such queue). Counts only; not audited per call (requested on every page). |

Every successful call (except the badge counts) writes an audit event: MAP_QUERY (filters, counts,
purpose), RECORD_VIEW (summary, details, record lists), SEARCH, OPERATIONAL_RECORD_CREATE,
OPERATIONAL_RECORD_REVIEW, NOTE_CREATE, NOTE_VIEW or DQ_ISSUE_FLAG. Every authorisation refusal writes
an AUTHZ_DENIED (or action-specific DENY) event. Requests rejected as malformed (422 validation) are
not audited; they reveal nothing and change nothing.

### Phase 6 workflow rules (ADR-036)

- Refusals: 403 without the permission over the item's territory (audited `AUTHZ_DENIED`); 404 for
  items outside every workflow permission's territory (audited); 409 `separation-of-duties` when the
  author decides their own review or the proposer approves their own action (audited
  `WORKFLOW_TRANSITION` DENY); 409 `invalid-state-transition` for a change the current state does not
  allow; 422 when finalising an outcome review without a baseline, an evidence reference or a
  conclusion of at least 20 characters (audited DENY `INCOMPLETE`).
- Every transition writes a `WORKFLOW_TRANSITION` audit event (before/after state; rationale length,
  never its text) and a `core.workflow_transition` history row in the same transaction.
- Free text refuses personal identifiers and references to individuals (as pattern reviews do).
- Queue priority: HIGH when overdue, or a pending review with 50+ records; MEDIUM within 7 days or 3+
  days old; otherwise LOW. A submitted review is due for a decision 7 days after submission; an
  action by its end date; an outcome review 28 days after the action ends.
- Operational records of kind `ACTION_COMPLETION` stay refused (422): completion is recorded on the
  action itself.
- Since the Phase 6 audit: database refusals (concurrent changes, trigger rules) are audited 409s;
  propose and approve validation refusals are audited (`INVALID_REQUEST`); outcome metrics and
  evidence links follow ADR-035 (`metrics_visible`, `category: null`); outcome edits clear a text
  field with `""`; `GET /actions/assignees` is audited. See ADR-036 (revised).

## 5. Auditing rules per endpoint type

| Endpoint type | Audit event |
|---|---|
| Any authorisation denial | `AUTHZ_DENIED` with permission, scope, reason |
| Record summary/detail view | `RECORD_VIEW` |
| Map and analytics queries | `MAP_QUERY` / `ANALYTICS_QUERY` with filters and counts |
| Search | `SEARCH` with query text (redacted if it looks like a personal identifier) |
| Writes and state transitions | A specific event per action (e.g. `OPERATIONAL_RECORD_CREATE`, `OPERATIONAL_RECORD_REVIEW`, `NOTE_CREATE`, `DQ_ISSUE_FLAG`, `DQ_ISSUE_UPDATE`, `BOUNDARY_APPROVAL`, `PRIVILEGE_CHANGE`) with before/after metadata, never free text |
| Export request / generation / download | `EXPORT_REQUEST`, `EXPORT_GENERATED`, `EXPORT_DOWNLOAD` |
| AI insight review / kill switch | `AI_INTERACTION`, `CONFIG_CHANGE` |
